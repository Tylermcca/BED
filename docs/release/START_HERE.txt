BED 0.5.0 - START HERE
================================

BED edits game data, 2D and 3D levels, and screens made in Gum. In 0.5,
New game gives you a small game with screens and settings ready to change.
Games set up for Live values and Game picture let you see what is happening
while they run. Use Help > Connect an AI app to connect your own assistant.
File > Export build makes a copy that can run without BED.


1. OPEN IT
----------
Double-click  BED.exe

BED needs Microsoft's Visual C++ Redistributable (x64), which most Windows PCs already have. If BED couldn't load VCRUNTIME140.dll or VCRUNTIME140_1.dll, install it from Microsoft: https://aka.ms/vs/17/release/vc_redist.x64.exe


2. TRY THE SAMPLE (two minutes)
-------------------------------
Click "Try the example" to open your own copy of a 3D level. You can
take the tour on the open example or explore it yourself.

  - Select the crate in the Outliner or the 3D view.
  - In Inspector, change Position X and press Enter.
  - Ctrl+Z undoes, Ctrl+Y redoes, Ctrl+S saves.
  - Ctrl+Shift+P finds a command by name.

To build from New game, install the Windows x64 .NET 10 SDK from
https://dotnet.microsoft.com/en-us/download/dotnet/10.0 and reopen BED.
Then choose Tools > Build and Play.

For your first settings change, follow samples/first-task/first_task.md in this folder.


2b. PLAY CHECKERS (a small game made with these tools)
------------------------------------------------------
Double-click Checkers in the sample list and open a position in Files.
In the Board panel, click a dark square to change what stands on it, or
choose Play in its own window to play from that position. You can also
double-click play-checkers.exe in samples\checkers.


2c. MAKE AND EXPORT A LEVEL
--------------------------
Keep the unpacked BED folder together, including samples and adapters.
"Try the example" opens a personal copy of the level. You can also open
the installed sample using the first step below.

  1. OPEN THE LEVEL
     Choose Open project (Ctrl+O) and select samples\scene-starter in this
     unpacked folder. In Files, select level.json and press Enter.

  2. ADD THE CRATE
     Press Insert outside a text field, or choose Scene > Add object.
     In the asset picker, select textured-crate.obj, then Add selected object.
     The cube and pillar are available too. Read any refusal in Assets before
     trying again; a missing model or texture must be fixed first.

  3. MOVE AND SAVE
     Select the new object in Objects or the 3D view. In Inspector, change
     Position X to 4.5 and press Enter. Ctrl+Z undoes; Ctrl+Y redoes.
     Press Ctrl+S to save the level. An object's position is relative to its
     parent when it belongs to a group.

  4. TRY PLAY
     Press Play. If there are drafts, choose Save, Don't Save or Cancel.
     Don't Save runs the saved level and keeps the draft in BED.
     The sample is a console program: the Play console prints
     "SceneStarter loaded saved level:" with object and mesh counts.
     It does not open a separate 3D game window. Choose Stop to end the run
     before editing or exporting again.
     For a quick run that exits by itself, open Tools > Play settings and
     use this Arguments (JSON list): ["--project",".","--seconds","0"].
     Save Play settings, then press Play. A successful run exits with code 0.
     If the program is missing or stale, use Build and Play and review the
     build prompt. Choose Show details to see the exact command. Read build
     errors in the console.

  5. EXPORT A BUILD
     Stop Play and save with Ctrl+S. Choose File > Export build... and press
     Build saved files. Wait for the build and unpacked-game check to pass.
     Enter a new or empty Destination folder outside the project, then press
     Copy build to folder... . BED refuses a folder that already has files.
     Cancel export stops an export in progress and keeps your level edits.

  6. RUN THE EXPORTED GAME
     Open PowerShell in that destination folder and run:

       .\SceneStarter.exe --project . --seconds 0

     It prints "SceneStarter loaded saved level:" and exits with code 0.
     This is the console sample loading your saved level and assets; it has
     no separate game window. You can close BED before running this copy.
     Keep the exported folder's data, .bed cache, program files and notices
     together. The framework-dependent export needs the .NET 10 runtime on
     the destination PC; it does not need BED.

Ctrl+W closes the level through its save decision. Select it in Files and
press Enter to reopen it. These models and the crate's texture are self-authored.


3. OPEN YOUR OWN DATA
---------------------
On the start screen, under "Open a project":

  Data folder     the folder of your JSON data files
  Rules folder (schema)   the folder of the rules for those files
  Link map        optional: a reference_map.json that says which fields name
                  items in other files (see the sample's for an example)

Use "Browse..." to choose each, then "Open".

Shortcut: if one folder holds  data\  and  schemas\  side by side, choose that
folder as the Data folder alone and click Open.

How a data file finds its schema: wares.json is checked by wares.schema.json,
or by the schema its "$schema" field names.

Projects you open are listed under "Recent projects" next time.

Keyboard: hold Ctrl and press Tab to choose Files, then release Ctrl. Tab or
Shift+Tab reaches its actions and rows; Enter activates the focused control.
New/Rename focus the name field; Enter there submits. Cancel or Escape goes
back to the opening action. Successful New/Rename focus the file row. Delete asks again:
Tab to Delete it and press Enter to confirm; focus then moves to Restore.
Restore focuses the restored row.

To close a project, choose Close project in Files. If it has unsaved edits,
Tab to Save all, then close; Close anyway; or Keep it open, and press Enter.
Escape while that prompt has focus keeps the project and its draft open.

If your adapter adds a map or 3D viewport, Tab to its outline. Enter selects
the next item; Shift+Enter the previous one. Arrows move a selected movable
item; Alt reverses snapping. Ctrl+arrows pan a zoomed-in map or orbit a 3D
viewport. =/+ and - zoom; Tab leaves. On maps only, 0 resets the view to its
current fitted bounds; Fit recomputes those bounds. These are visual keyboard
controls, not a screen-reader bridge.


4. WHEN SOMETHING'S WRONG
-------------------------
  - A file that can't open is marked in the Files panel; hover over it to see why.
  - A file that doesn't fit its schema has a "Repair" button: it opens anyway,
    and lets you fix it one edit at a time.
  - Saving is refused if the file was changed by another program since you
    opened it, so nobody's work is overwritten.


USE IT WITH AN AI ASSISTANT
---------------------------
With a project data file open in BED, Help > Use with an AI assistant shows setup examples for that project; the start-screen Help button uses the bundled sample.
Open guides/using_bed_with_ai.md in this folder for a step-by-step guide.
It covers bed-cli.exe, the sample, and local MCP setup for your assistant.
Start with a copy. Preview edits and approve writes before saving.
Some file tools can write immediately: read the guide's saves and limits.
Adapters are programs; load only ones you trust.


5. MORE
-------
  - A game can add its own rules and panels with an ADAPTER: a DLL put in the
    adapters folder. The bundled recipes, checkers, first-task and level
    samples include their own adapters. Only add adapters you trust.
  - Without a window (for scripts or trials): BED.exe --help lists
    its options. <folder> --shot picture.png draws the screen into a picture;
    --settings <folder> keeps the recent list there instead of your own.
    A picture is all --shot gives: choosing a recent project or playing a match
    needs the window.
  - licenses\THIRD-PARTY-NOTICES.md lists the libraries this uses and their licences.
